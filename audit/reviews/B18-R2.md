## Required changes
1. [AUD-48] plugins/command_injection_plugin.py:run(), `has_exec_proof`: the generic signatures `"uid=", "uid=0(root)", "root:x:0:0", "Windows IP Configuration"` and the fixed tokens are accepted without checking whether they also appear in the inert control response `inert_resp`. Traced case: an endpoint that reflects `q` on a page with a static link `href="/profile?uid=7"` gives `is_reflector=True` and `has_exec_proof=True` (because `"uid="` is present), so it is reported as a Critical, high-confidence OS command injection. That is the reflection false positive AUD-48 is meant to remove, and it breaks the spec rule "a marker that also appears in the control is reflection".
   - Expected: a proof token counts only if it is present in `response.text` **and absent** from `inert_resp.text`. If `inert_resp` is None, treat that as "no control" and don't report as high confidence.
   - Expected: replace bare `"uid="` with a strict pattern such as `re.search(r"uid=\d+\(\w+\)\s+gid=\d+", text)`.
   - Apply the same control-absence rule in the JSON-body path at ~line 150.
   - Checked next round by: a unit test whose fake server echoes `q` inside a page that always contains `href="/profile?uid=7"` (and, as a separate variant, `root:x:0:0`) yields 0 command-injection findings. The existing echo-and-run, echo-only and testbed tests must still pass.
2. [AUD-50] test_b18_accuracy.py: R1 required change #4 for AUD-50 was not done. No test runs the real plugins against `testbed.app.app` and then `merge_canonical`. `test_aud50_multiple_issue_deduplication` builds idealized `Finding`s by hand: titles and types the fixer chose, `/api/exec` with `method="POST"` even though `command_injection_plugin.parse_output` emits `"GET"` unless "body" is in the result, and no security-header findings at all. So the acceptance criterion "a real testbed scan reports `/.env`, `/admin`, `/api/exec`, the IDOR, and each missing header exactly once" is unverified.
   - Expected: add a test that runs the full real plugin set against `testbed.app.app`, using the existing `make_flask_safe_request` adapter patched onto `BaseScanner._safe_request` with `_verify_timing` patched out. Collect findings via `Engine._dict_to_findings` (or `run_plugins`), apply `Correlator().merge_canonical`, then assert exactly 1 finding for each of: `/.env`, `/admin`, `/api/exec` (command_injection), `idor` on `/api/users/{id}`, and **each** missing-header param (case-insensitive) that any plugin reported.
   - If that exposes key mismatches between plugins (for example, header titles that infer to different vuln_types), fix them through the taxonomy or alias table, not through endpoint or title overrides.
   - Checked next round by: running that test, and checking that it fails if `merge_canonical` is replaced with the identity function.
