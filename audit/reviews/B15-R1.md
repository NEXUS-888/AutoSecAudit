## Required changes
1. [AUD-40] `core/pipeline.py:run_scan_pipeline` and `ui/app.py:_run_scan_background` — the base code stopped the scan at 4 checkpoints when the job was marked as errored. That happens on a timeout, via the sweeper at `ui/app.py:271-279`, or on cancel. The new code removed all 4 checkpoints. A timed-out or cancelled UI scan now runs every plugin to the end, writes JSON and HTML to `data/reports/`, and sets `job["report_name"]` on a job already marked as errored. → Add an optional `cancel_check: Optional[Callable[[], bool]] = None` to `ScanRequest`. The pipeline must check it before plugins, after plugins, after report generation and before saving. If it returns true, stop without writing any report file, by raising a dedicated exception or returning early. `_run_scan_background` must pass `cancel_check=check_cancelled` and must not set `report_name` on a cancelled job. (Checked next round by: a new test that passes a `cancel_check` that returns `True` after the `"scanning"` stage, then asserts that no `scan_*.json` or `report_*.html` was created in a patched `config.REPORTS_DIR` and that the run stopped. Also by `grep -n "check_cancelled" ui/app.py`, which must show it used, not just defined.)

## Notes
- `ScanRequest.treat_dev_artifacts_as_info` (`core/pipeline.py:73`) is never read by the pipeline, so drop it or use it. Also, `main.run_scan` still runs its own scope and reachability checks before calling the pipeline (`main.py:80-104`), so a live target is probed twice.
- The `"--login-pass" in sys.argv` check (`main.py:76`) misses the `--login-pass=secret` form. Test whether any argv entry starts with `--login-pass`.
- The UI no longer sends its auth-result and crawler-count SSE events (`Authenticated! Captured session…`, `Discovered N endpoints…`). It also no longer uses the 2.5 s reachability timeout. Consider sending these from the pipeline through `emit`.
