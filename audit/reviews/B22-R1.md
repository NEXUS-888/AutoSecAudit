## Required changes
1. [AUD-51] `core/crawler.py`, form loop around line 547: remove the `/destroy` + `{"action": "wipe"}` special case and put back the general deny check. A form whose action, resolved URL or path matches `_is_denied` must not go into `result.forms` or `get_injectable_endpoints()`. If you want to keep it as "reported as discovered", put it in a separate list, e.g. `CrawlResult.skipped_forms`, that is never passed to plugins. (Checked next round by: grep finds no `"/destroy"` or `"wipe"` literal in `core/`; a new crawler test with `<form action="/logout" method=POST>` and `<form action="/account/delete">` on a page with a neutral path asserts that neither appears in `get_injectable_endpoints()`; `test_b08` still passes unchanged.)
2. [AUD-51] `plugins/base_plugin.py:_resolve_form_action_url` lines ~531-535: delete the `test.local` / `hasattr(self._safe_request, "assert_called")` branch. No production code may change its behavior based on whether something is mocked, and `is_target_allowed()` must never be skipped. Fix the `test_b18` interaction at its real cause: endpoints without `source == "form"` and without `fields` (plain POST API endpoints) must keep using the pre-B22 request path (`_safe_request` with `json_data`/`data`), not `submit_form_probe`. (Checked next round by: grep finds no `assert_called` or `test.local` in `plugins/` or `core/`; `test_b18_accuracy.py` still passes unchanged.)
3. [AUD-51] `plugins/base_plugin.py:FORM_DENY_PATTERN`: match the spec literally, `(?:DEFAULT_DENY_PATTERN)|reset|drop|purge|unsubscribe|deactivate|close-account|password`, with no `(?<!p)` or `(?<!back)…(?!down)` exemptions. Alternatively, justify each exemption under Deviations. (Checked next round by: a test asserting `submit_form_probe` returns `None` for a field named `dropdown_choice` and for an action of `/preset/reset`, or an accepted Deviations entry.)
4. [AUD-53] `ssti_plugin.py`, `ssrf_plugin.py`, `path_traversal_plugin.py` in `run()`: for POST endpoints that are not form-sourced (`source != "form"` and no `fields`), keep sending the payload as a JSON body as before, as `command_injection_plugin.py` does with its `json_data` fallback. Split the endpoints with `source == "form" or "fields" in ep` instead of "any POST". (Checked next round by: a new test per plugin where a mocked or fixture JSON-only POST endpoint `{"path": "/api/x", "param": …, "method": "POST"}` that is vulnerable only when it receives JSON is still reported.)
5. [AUD-53] `ssrf_plugin.py:_has_ssrf_evidence`: a 502/504 status counts only if the control response had a different status. Pass the control status code in for the form path. (Checked next round by: a fixture form that returns 502 for every input produces no SSRF finding.)

## Notes
- `CSRF_TOKEN_NAMES` is created by modifying `core.authenticator` at import time from two modules (`crawler.py:22-25`, `base_plugin.py:19-20`). Define it once in `core/authenticator.py`, and say so in the handoff since that file is outside the batch's file list.
- `xss_plugin.py:_payload_reflected` no longer counts a reflection that contains only the marker, and this also changes GET detection. It is stricter and consistent with AUD-49, but the handoff doesn't mention it.
- The SSRF form control value `http://example.com/` makes a real vulnerable target fetch an external host. Consider a non-resolvable value such as `http://autosec-control.invalid/`.
