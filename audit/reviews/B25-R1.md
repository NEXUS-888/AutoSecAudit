| AUD-60 | FAIL | The ground-truth table lists `/api/v1/_debug` as a Real Vulnerability (`testbed/app2.py:18`), but no test asserts it is reported. The session-cookie check is `>= 1`, not exactly once (`test_b25_regression_testbed.py:183-184`). The off-origin spy only wraps `ScanHttpClient.request` (`test_b25_regression_testbed.py:111`). The decoy checks are too narrow: `/go` is only checked for `open_redirect`, and CSRF is filtered on `"form" in title` (`:192`, `:196`). `/login` accepts any non-empty credentials (`testbed/app2.py:72`), so the scan "with login credentials" cannot catch an authenticator that sends the wrong password. A change outside the batch scope also weakens a detector: the static-navigation filter in `plugins/xss_plugin.py:220-226` captures only the first quoted literal. Traced by hand (I couldn't run it), `location.href='/x?c='+document.cookie` captures `'/x?c='`, which counts as static, so a real DOM sink gets suppressed. This change is not listed under Deviations. |
| AUD-61 | PARTIAL | `validate_login_url` (`core/authenticator.py:134-180`) is wired into `authenticate()` (`:267-275`) and `run_scan` (`main.py:85-91`), and `main()` passes the exit code through `sys.exit(main())` to the process. Tests in `TestB25LoginUrlValidation` cover all five listed values, the `AuthResult` message and the subprocess exit code. The gap is the origin check, which compares only `netloc` (`core/authenticator.py:~165`). `https://127.0.0.1:5103/login/` is therefore accepted for an `http://127.0.0.1:5103` target, even though a different scheme is a different origin. |

## Required changes
1. [AUD-60] `test_b25_regression_testbed.py:111` — the off-origin spy wraps `ScanHttpClient.request` only, so the crawler, authenticator, SPA detector, OpenAPI importer, engine probe and followed redirects are not recorded → wrap `requests.adapters.HTTPAdapter.send` (or `requests.Session.send`) for the whole pipeline run, record `urlparse(prepared.url).netloc` for every request, and assert the set equals `{fixture_netloc}` (checked next round by: reading the spy target and checking it is restored in `finally`).
2. [AUD-60] `test_b25_regression_testbed.py:~186` — the planted `/api/v1/_debug` unauthenticated user-records exposure (ground-truth row at `testbed/app2.py:18`) has no assertion → assert exactly one finding whose endpoint is `/api/v1/_debug`. If no scanner reports it, fix the detector rather than deleting the ground-truth row (checked next round by: the assertion exists and the test passes).
3. [AUD-60] `test_b25_regression_testbed.py:183-184` — the session cookie check uses `assertGreaterEqual(..., 1)` and matches on title/param text → assert exactly one cookie-flag finding for `session_token`, even though both `/` and `/login` set the cookie (checked next round by: `assertEqual(len(cookie_findings), 1)`).
4. [AUD-60] `test_b25_regression_testbed.py:192-199` — the decoy assertions are too narrow → assert zero findings of any type whose endpoint is `/go` or `/go/`, and zero findings with `vuln_type == "csrf"` whose endpoint is `/login`, with no title filter (checked next round by: reading the two filters).
5. [AUD-60] `testbed/app2.py:72` — `or (username and password)` accepts any credentials → accept only `admin`/`admin` and return 401 otherwise, so the authenticated scan proves the right credentials were sent (checked next round by: the code, plus a small test that POSTs wrong credentials with a valid CSRF token and expects 401 with no session cookie).
6. [AUD-60] `plugins/xss_plugin.py:220-226` — the static-navigation filter treats `location.href='/x?c='+document.cookie` and `window.location='/a'+location.hash` as static → treat an assignment as benign only if the whole right-hand side, up to `;`, `"` or the end of the attribute, is a single quoted literal with no `+`, template literal or concatenation. Add a unit test showing both strings are still reported while `window.location.href='/labs/sqli'` is not. Also list this change under Deviations with its reason (checked next round by: the new unit test).
7. [AUD-61] `core/authenticator.py:validate_login_url` — the origin check compares `netloc` only → compare `(scheme.lower(), hostname.lower(), effective port)`, with the default port 80/443 filled in, against the target. A different scheme is rejected with the value in the message. Add a test that `https://127.0.0.1:5103/login/` is rejected for target `http://127.0.0.1:5103` (checked next round by: the new test case).
