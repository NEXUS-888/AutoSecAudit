## Required changes
1. [AUD-15] `ui/app.py:_get_client_ip` (line 83) — the throttle key comes from the client-supplied `X-Forwarded-For` header, so an attacker who rotates the header (e.g. `X-Forwarded-For: 10.0.0.N`) skips the 5-failures-per-5-minutes limit completely. → Key the throttle on `request.remote_addr` only. If proxy support is wanted, make it opt-in with werkzeug `ProxyFix` behind an explicit config flag (default off), and don't parse XFF by hand. (Checked next round by: a new test that sends 6 bad logins from one `REMOTE_ADDR` with a different `X-Forwarded-For` on each, and expects the 6th to return 429.)
2. [AUD-13/14/15] `test_b05_web_hardening.py` — `TestCSRFProtection`, `TestOpenRedirect` and `TestUnsafeServerDefaults` don't inherit `unittest.TestCase`, so the project runner's unittest discovery finds 0 of them. That's why the precheck total is 183, the same as baseline, while pytest counts 200. `pytest` is also not in `requirements.txt`. → Make each class inherit `unittest.TestCase`: rename `setup_method`/`teardown_method`/`setup_class`/`teardown_class` to `setUp`/`tearDown`/`setUpClass`/`tearDownClass`, and drop `import pytest`. (Checked next round by: the precheck total in `python run_tests.py` must be at least 183 + 17, with 0 failures.)

## Notes
- The demo admin credential hints were removed from `auth.html` and `landing.html`. That's reasonable hardening but outside this batch's scope; it should be mentioned in the handoff rather than slipped in.
