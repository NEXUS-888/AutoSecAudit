## Required changes
1. [AUD-81] `core/pipeline.py:run_scan_pipeline` has two problems:
   - **Cleanup gap:** cleanup covers only the final `cancel_check()` at line 353. Any `ScanCancelledError` raised after `json_path`/`html_path` exist, for example from an `emit(...)` in the report/save stage, leaves complete-looking `scan_*.json`/HTML files in `REPORTS_DIR`. The webhook also sends a "completed" notification for cancelled scans.
   - **Expected:**
     - Wrap everything from the first report write up to `emit("done")` in `try/except ScanCancelledError`. The handler removes `json_path`, `html_path` and any PDF, then re-raises.
     - Move the cancel check before the webhook.
   - **Re-checked next round by:** a new test in `test_ux_cancel_scan.py`. It uses a `generator_cls`/engine stub that sets the job to cancelled during report generation, after the JSON is written. It asserts:
     - final status is `cancelled`
     - `os.listdir(REPORTS_DIR)` shows no new files
     - the scan is absent from `/history`
     - the webhook is not called (patched `WebhookNotifier`)

## Notes
- `REPORT_ID_PATTERN` (`ui/app.py:307`) was widened to allow dots for every report route, and the handoff's Deviations does not mention it. The `..` lookahead and the lack of `/` keep it traversal-safe, but justify the change or revert it.
- `/compare/../etc/passwd/...` is normalized by the client and never reaches the validator. Add a case such as `/compare/bad$id/<new>` so the 404 path is actually exercised.
- Race: `cancel_scan` can return 200 between `emit`'s `check_cancelled()` and `_emit_job_event(..., status="done")`. The scan then finishes as `done` with a report. Consider making the done transition and the cancel check atomic under `scan_jobs_lock`.
