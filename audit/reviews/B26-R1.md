## Required changes
1. [AUD-69/70] `benchmark/run_benchmark.py:run_single_benchmark` — accepts non-loopback private hosts such as `http://192.168.1.10` or `http://10.0.0.5`, and possibly allowlisted practice hosts, because only `is_target_allowed` is checked. → Add an explicit loopback check before `is_target_allowed`: hostname is `localhost`, or every resolved IP is in 127.0.0.0/8 or `::1`. Otherwise print "not a loopback target" and exit 1. Raise or return an error instead of calling `sys.exit` inside the library function, and exit only in `main()`. (Checked next round by: a CLI subprocess test with `--url http://192.168.1.10` and `--url http://10.0.0.5` asserting a non-zero exit and "loopback" in stderr, plus a unit test of the helper that accepts `127.0.0.2` and `localhost`.)
2. [AUD-69] `benchmark/metrics.py:normalize_benchmark_endpoint` and the cookie fallback in `compute_metrics` — every `insecure_cookie` finding matches any cookie truth item regardless of endpoint. The spec requires `(vuln_type, normalized endpoint)` matching and Deviations says "none". → Match cookies by endpoint like other types and fix the truth endpoints if needed. Alternatively, document a justified deviation in the handoff and add a test showing a cookie finding on an unrelated endpoint is still handled as intended. (Checked next round by: reading the diff and the Deviations section, and a metrics test for a cookie finding on `/other`.)
3. [AUD-70] `test_benchmark.py:test_runner_url_mode_against_local_testbed1` — does not exercise `--url` and does not assert "same metrics as built-in mode". → Run `python -m benchmark.run_benchmark --url <srv.base_url> --truth testbed1 --output <tmp>.json` via subprocess against a started testbed1. Then assert that `true_positives`, `false_positives`, `false_negatives`, `matched_items`, `precision`, `recall` and `f1` equal those from `run_builtin_testbed("testbed1")["metrics"]`. (Checked next round by: reading the test.)
4. [AUD-70] `benchmark/ground_truth/vampi.json`, `vulpy.json`, `pygoat.json` — items are not "as documented by each project":
   - **VAmPI:** the `/config` route doesn't exist upstream. Its SQLi is on `/users/v1/{username}`, not on login or books. The excessive data exposure on `/users/v1/_debug` is missing.
   - **vulpy:** the `/search`, `/admin` and `/user/profile` routes don't appear upstream. A "CSRF-token protected login" decoy contradicts vulpy's bad version.
   - **Placeholder matching:** non-numeric path params like `{username}` can't match after normalization.

   → Add a `"source"` field to each item, citing the upstream doc or route file, and correct or remove unsupported items. (Checked next round by: spot-checking `source` against upstream route definitions, and the schema test requiring `source` on external-app files.)
