## Required changes
1. [AUD-22] `core/authenticator.py:_verify_authenticated_session`, the `is_mock_return_val` lines (~587-589): production code must not detect test doubles. Delete the branch. A token counts as verified only when `anon_status in (401, 403)` (or anon redirected to login) and the verify request with the token returns 200. Fix `test_json_api_login_success` in a strengthening direction only: give its mock `get` a `side_effect` that returns 401 without `Authorization` and 200 with it. Leave its assertions untouched. (Checked next round by: grep for `side_effect`/`return_value` in `core/authenticator.py` finds no hits, and the full suite passes.)
2. [AUD-22] `core/authenticator.py:_verify_authenticated_session`, branch E (~593-595): cookies plus `verify_resp.status_code == 200` must not be enough. The verify result has to differ from the anonymous baseline: status changed (401/403/redirect-to-login → 200), final URL moved off the login page, or a logout link or the username is newly present. The only acceptable fallback is a material body difference from `anon_text`. Failing case: root always returns 200 "Home page", and the POST rotates `sid` and returns 200 "Those details don't match our records". This currently gives `success=True` and must give `success=False`. (Checked next round by: a new test with exactly that mock asserting `success == False`.)
3. [AUD-23] `core/authenticator.py:_try_login_at_endpoint` (~292-322): during auto-discovery (no explicit `login_url`), only submit to a JSON endpoint when the empty `json={}` POST returns 400, 401 or 422. Drop `is_json_resp` as a qualifier. Keeping the `explicit_login_url` exemption is fine, but record it under Deviations. (Checked next round by: a test where every path's GET returns 200 `{"status":"ok"}` and the empty POST returns 200, asserting zero credential POSTs.)
4. [AUD-23/AUD-22] `core/authenticator.py:_attempt_json_api_login`: real Juice Shop reads only `req.body.email` and returns 401 "Invalid email or password." to `{"username": …}`. So the current code stops before it ever sends `{"email": …}`, and real Juice Shop auto-login fails. The new Juice Shop test mock (`test_b08_auth_and_crawler.py:~62`) accepts any non-empty body, which hides this. Expected: when the username contains `@`, send the `email` variation first (or otherwise pick the field from the endpoint's shape). Keep the stop-on-rejection and the cap of 6. (Checked next round by: a test whose POST mock returns 401 "Invalid email or password." unless the body has an `email` key, asserting `success == True`, token captured, ≤ 6 credential POSTs.)

## Notes
- The crawler's deny regex matches the whole URL, host included. A target host like `remove-me.lab` or `delete.local` would block the entire crawl, including the start URL. Consider matching only the path and query.
- Same-origin redirects are still followed automatically: the default `allow_redirects` is on, so a link that 302s to `/logout` gets requested. That's not required by AUD-24 as written, but checking redirect `Location` against the deny pattern would close the gap.
- `_is_clear_credential_rejection` (`core/authenticator.py:101`) is never called. The handoff also says `DEFAULT_DENY_PATTERN` was added to the authenticator, but it isn't in the diff.
