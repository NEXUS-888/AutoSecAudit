## Required changes
1. [AUD-79] `test_ux_finding_triage.py`: three tests don't prove what they claim.
   - `test_default_state_is_open` only checks the testid. `"false_positive"` always appears as an `<option>` value, so the persistence check is vacuous.
   - The control is checked once, not per finding.
   - **Expected:** assert `html.count('data-testid="finding-triage"') == 2` and `data-triage-state="open"` for both findings by default.
   - **Expected:** after a POST, assert `data-finding-id="FINDING-002"` card has `data-triage-state="false_positive"`. Do this from a client built after reloading or recreating the app (e.g. `importlib.reload` or a fresh `app.test_client()` with no shared state).
   - Also assert the sidecar contents after clearing to open.
   - **Checked by:** reading the assertions.
2. [AUD-79] `ui/app.py:triage_finding` has two 500 paths.
   - A non-dict JSON body (e.g. `[1]`) hits `payload.get` → 500.
   - A non-string `finding_id` (list or dict) makes the set membership test raise `TypeError` → 500.
   - **Expected:** `if not isinstance(payload, dict) or not isinstance(finding_id, str): return 400`.
   - **Checked by:** new test cases posting `[1]` and `{"finding_id": ["x"], "state": "open"}`, both expecting 400.
3. [AUD-79] The sidecar is named `scan_<id>.triage.json`.
   - This matches `scan_*.json` listing globs (history, MCP, delta).
   - It also matches the `_resolve_report_data` candidate `{report_id}.json` for id `scan_<id>.triage`. The triage map could then be loaded or rendered as a report, possibly an ownerless one, which leaks notes.
   - **Expected:** use a name or directory that no report glob or resolver candidate matches (e.g. `REPORTS_DIR/triage/<clean_id>.json`).
   - **Checked by:** a test that POSTs a triage, then asserts:
     - `/history` shows no extra entry;
     - `GET /report/scan_<id>.triage` returns 404.
4. [AUD-79] `reports/templates/report.html` puts `'{{ finding.id }}'` inside `onchange`/`onclick` attribute JS.
   - The browser HTML-decodes `&#39;` before the JS runs, so an id containing `'` injects script.
   - `querySelector('[data-finding-id="' + id + '"]')` is also unescaped.
   - **Expected:** handlers read `this.closest('.finding-card').dataset.findingId`, and selectors use `CSS.escape(id)`.
   - **Checked by:** grepping the template for `('{{ finding.id }}'`, which should return 0 hits.
5. [AUD-80] `test_ux_compare_scans.py` doesn't check the prepared pair's results.
   - **Expected:** for old→new, the summary numbers are New=1, Fixed=1, Unchanged=1. Each section contains exactly the expected title: Open Redirect in New, SQLi in Fixed, HSTS in Unchanged. Slice the HTML between section headings to check this.
   - **Expected:** for new→old, assert SQLi is in New and Open Redirect is in Fixed.
   - **Checked by:** reading the assertions and running the test.
6. [AUD-81] `test_ux_cancel_scan.py` doesn't exercise a real scan.
   - **Expected:** start a real scan via `POST /scan`, using a slow mocked engine whose loop calls `cancel_check`. Then `POST /scan/cancel/<id>` and poll for completion.
   - **Expected assertions:**
     - final `job["status"] == "cancelled"` within about 5 s (not `error` or `done`);
     - no new file appears in `REPORTS_DIR` and `/history` is unchanged;
     - `_scan_executor.can_accept()` is True after the thread exits;
     - a second `POST /scan` succeeds.
   - **Checked by:** reading and running the test.
7. [AUD-81] `ui/app.py:_run_scan_background` may not respect a late cancel.
   - A cancel that lands after the last engine `cancel_check` can still persist the report.
   - The completion or except paths may overwrite `"cancelled"` with `"done"`/`"error"`.
   - **Expected:**
     - call `check_cancelled()` right before saving the report and before setting `done`;
     - the `ScanCancelledError` handler keeps the status as `cancelled`;
     - the `cancel_scan` endpoint returns 409 for `error` as well as `done`.
   - **Checked by:** the diff, plus the test in item 6.
8. [AUD-81] `ui/app.py` `HTML_FORM` `cancelCurrentScan` calls `handleScanCancelled()` on any response, including 409, 403, network errors and the `.catch` path.
   - The UI then claims "Scan cancelled" and closes the SSE for a scan that actually completed.
   - **Expected:** only call `handleScanCancelled()` when `r.ok`. Otherwise restore the button and show the error message.
   - **Checked by:** reading the JS.

## Notes
- The triage read-modify-write has no lock and no atomic replace. Also, a failed load resets the map to `{}`, so a corrupted file silently wipes all prior triage on the next save. Use a lock plus a temp file and `os.replace`.
- The `_resolve_report_data` candidate expansion (`scan_{report_id}.json`, `report_{report_id}.json`) is an undeclared change to a shared resolver. It appears to exist only to fit the test fixture ids, so list it under Deviations.
- `cancel_scan` returns 403 for another user's job, while `scan_status` returns 404. Use 404 so the response doesn't reveal which scan ids exist.
