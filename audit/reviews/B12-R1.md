## Required changes
1. [AUD-32] `plugins/base_plugin.py:_verify_against_baseline` step 1 (`:310`): any 5xx is verified as high, even when `status_codes` already contains that status (unstable baseline) or `control_status` is the same 5xx. For example, an app that returns 500 for any unexpected input, including the benign control, gets a high finding. → A status change counts only if `mal_status not in status_codes` and `mal_status != control_status`. (Checked next round by: unit tests where baseline `status_codes=[200,503]` with a 503 probe → `False`, and `control_status=500` with a 500 probe → `False`. The existing 200→500 test must still pass.)
2. [AUD-32] `plugins/base_plugin.py:363-367`: the control comparison only rejects a probe whose length matches the control's to the byte. Example: baseline length 1000, control length 400 ("Not found" page), probe length 401 with the same body plus 1 byte. Result today is `(True,"medium")`, which is a false positive. → Reject when the probe is close to the control: length difference ≤ the observed variance (or ≥ a small floor), or `SequenceMatcher` ratio against `control_content` ≥ a threshold, whichever the fixer picks. Apply this to the status-changed path too. (Checked next round by: a unit test with the scenario above that asserts `False`.)
3. [AUD-32] `plugins/base_plugin.py:344-357`: the significance verdict uses only `raw_length_ratio`, so the required similarity ratio plays no part in the main decision. → In addition to length, compute `SequenceMatcher` on the bounded prefix between the discounted probe and the baseline. Treat a change as significant only if that similarity is below the baseline samples' own similarity (`sample_similarity`, or one computed from `samples`) by a margin. (Checked next round by: a unit test where two baseline samples share a template but differ in a token, and a probe with the same template and a different token, within length variance, is not verified. Plus a grep showing `sample_similarity` or an equivalent is read in `_verify_against_baseline`.)
4. [AUD-32] `plugins/sqli_plugin.py:151`: `self._verify_against_baseline(baseline, resp)` does not pass the payload, so reflection discounting is dead in production. → `self._verify_against_baseline(baseline, resp, payload=payload)`. Grep every other caller and do the same. (Checked next round by: grep that every call passes `payload=`.)
5. [AUD-33] `core/timing.py:TimingTrafficController` + `core/http_client.py:235`: timing probes still overlap concurrent traffic. → Either (a) the client tracks in-flight requests (counter plus condition), and `pause_other_traffic()` waits until the other threads' in-flight count reaches 0 before returning; the gate check must also come after `pace_request()` (or be repeated after it), right before `_execute_with_redirects`. Or (b) timing plugins call `engine.register_timing_check(...)`, and the engine runs them after the executor joins, with the results merged into `scan_results`. Remove `register_timing_check`/`run_timing_checks` if it stays unused under (a). (Checked next round by: a unit test where a fake request in another thread is in flight when `serialized_timing_phase()` is entered. The test asserts the phase body starts only after that request completes, and that a new request from the other thread blocks until the phase exits.)
