## Notes
- I couldn't run any Python myself because Bash and PowerShell were denied in this mode, so the verdicts rest on reading the code plus the driver's precheck (169 tests, 0 failures). Separately, on unpatched interpreters older than 3.10.15 or 3.11.10 (CVE-2024-4032), `IPv6Address("::ffff:8.8.8.8").is_private` is True, which would let `http://[::ffff:8.8.8.8]/` through. Hardening would mean normalizing with `ip = ip.ipv4_mapped or ip` before the private/loopback check, plus a test for it.
- The acceptance test for the public-looking names (`10.example.com` and the others) depends on live DNS. They are rejected today only because they don't resolve. Two tests are missing: a mocked `getaddrinfo` that resolves `10.example.com` to a public IP, and a mixed private+public answer that checks the "every address" rule.
- Not required now: the check runs once and later requests resolve DNS again, so DNS rebinding can still bypass it (time-of-check vs. time-of-use). Hostnames with underscores, such as compose service `juice_shop`, are rejected by `_is_valid_hostname`. `handle_verify_fix` now relies on the dispatcher's generic `except` (`mcp_server.py:367`) to report disallowed targets.
