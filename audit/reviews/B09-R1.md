## Required changes
1. [AUD-25] `core/politeness.py:PolitenessEngine.pace_request`: this is per-call jitter with the sleep outside the lock, and no state is shared across threads. → It must be a real global limiter. Keep a shared `_next_allowed_at` under `self._lock`, have each caller reserve the next slot `max(now, _next_allowed_at) + interval`, then sleep until its slot outside the lock. Requests from all plugins sharing the client must then be spaced at least `interval` apart. (Checked next round by: a new test that fires 10 concurrent `client.request` calls from a `ThreadPoolExecutor` at a local `ThreadingHTTPServer` with pacing set to 100 ms. It asserts that the gaps between server-side arrival timestamps are each ≥ ~90 ms.)
2. [AUD-25] `core/http_client.py:is_in_scope` / `_execute_with_redirects`: a malformed redirect `Location` (bad port, unparsable URL) raises `ValueError` through `_safe_request`. → `is_in_scope` must return `False` on any parse error (`try: … url_parsed.port … except ValueError: return False`), and the redirect is then treated as out of scope and not followed. `request()` must never raise to plugins. (Checked next round by: a live local-server test where `Location: http://127.0.0.1:99999/x` returns the 302 or `None` without raising.)
3. [AUD-26] `core/http_client.py:197` and `core/engine.py`: `throttled_count` is not reported and is updated without a lock. → Increment it under a lock. The Engine must expose `self.http_client.throttled_count` in the scan output (the report dict or `ScanResult` summary, e.g. a `throttled_requests` key) after `run_plugins`. (Checked next round by: a test that runs the Engine against a mocked always-429 send and asserts that the count appears in the result.)
4. [AUD-26] `test_b09_shared_http_client.py:test_aud26_always_503_server_returns_none`: the test passes without the code under test being involved. → Set `client.session.send = MagicMock(return_value=resp_503)` (with `time.sleep` patched or `Retry-After: "0.01"`). Assert `resp is None`, `send.call_count == max_retries_on_429 + 1`, and that `throttled_count` increased. (Checked next round by: reading the test and confirming that `send` is mocked and the call count is asserted.)
5. [AUD-26] `core/http_client.py:66,71` / `core/engine.py:34`: `max_retries_on_429` exists in two places and the `PolitenessEngine` one is still unused. → Use one source. Default the client's retry limit to `self.politeness.max_retries_on_429` when no explicit value is passed. (Checked next round by: `ScanHttpClient(politeness=PolitenessEngine(max_retries_on_429=1))` with a mocked always-429 send calls `send` exactly 2 times.)

## Notes
- The scope check runs only on redirect hops. The first URL passed to `request()` is not checked. A plugin that requests a crawler-discovered external link would still hit it with the shared auth headers. Running `is_in_scope` before the first send would close this gap cheaply.
- `get_authenticated_session()` now returns the shared Session itself. Plugins that call `session.get()` directly still follow redirects automatically with no scope check, and target `Set-Cookie` responses to attack payloads now change the cookie jar for all plugins. This is not a regression for this batch, but it should be tracked.
- I measured the rate-limiter behavior only by reading the code. My one concurrency timing run was inconclusive: 20 requests with 100 ms pacing on 20 threads took 1.13 s. A second, cleaner measurement was blocked by permissions. The finding in gap (a) follows directly from the sleep being outside the lock with no shared timestamp.
