## Notes
- Every caught `Timeout` from `session.send` increments `requests_timed_out` (`core/http_client.py:809-816`), including an ordinary per-read socket timeout that has nothing to do with `MAX_REQUEST_SECONDS`. AUD-59 should decide whether that counter means "wall-time limit hit" or "any timeout". Also still open from round 1: a body cut short by the time limit does not increment `responses_truncated`.
- `requirements.txt:7` still allows `urllib3>=2.0.0`. On 2.0.x there is no `read1`, so the body falls back to `iter_content`, where only the watchdog bounds the time. That still works, because the socket is registered, but it isn't tested. Consider pinning `urllib3>=2.1`. There is also a tiny race: if the timer fires between `resp.close()` returning the connection to the pool and `__exit__`, it can shut down a pooled keep-alive socket, and the next request on that connection would hit a dropped connection.
