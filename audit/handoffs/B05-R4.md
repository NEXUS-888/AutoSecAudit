# Handoff B05 round 4

## Summary of changes
- Addressed all concurrency and persistence feedback from Round 3 review:
  1. Converted login throttling to an atomic reservation model (`ui/app.py:_reserve_login_attempt`). Checking the failure threshold and recording the attempt timestamp now happen under a single acquisition of `LOGIN_FAILURES_LOCK` before calling `auth.verify_user`, eliminating the check-then-act concurrency race.
  2. Added concurrency stress test (`test_login_throttling_parallel_threads_race_free`) launching 15 parallel threads synchronized behind a `threading.Barrier` with artificial password hashing delay, verifying that at most 5 requests return 401 and the rest return 429.
  3. Hardened `config.py:_get_or_create_secret_key` with `os.open(..., os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)`, guaranteeing atomic restricted file creation and handling multi-process creation races.
  4. Added periodic pruning of stale IP buckets in `ui/app.py` when tracking table exceeds 1,000 IPs.

## Per-issue details
### AUD-13 (No CSRF protection)
- **Approach**: Flask-WTF `CSRFProtect` integration in `ui/app.py` via `AutoSecCSRFProtect`, protecting all state-changing endpoints (`/login`, `/register`, `/scan`, `/scan/async`). Supports hidden input `csrf_token`, headers (`X-CSRFToken`), and JSON payloads. Can be disabled via `app.config["WTF_CSRF_ENABLED"] = False`. Tested via `unittest.TestCase` discovery.
- **Files touched**: `requirements.txt`, `ui/app.py`, `ui/templates/auth.html`, `ui/templates/landing.html`, `test_b04_auth.py`, `test_target_reachability.py`, `test_silent_failures.py`
- **Tests added**: `test_b05_web_hardening.py:TestCSRFProtection::test_post_login_without_csrf_returns_400`, `test_b05_web_hardening.py:TestCSRFProtection::test_post_register_without_csrf_returns_400`, `test_b05_web_hardening.py:TestCSRFProtection::test_post_scan_async_without_csrf_returns_400`, `test_b05_web_hardening.py:TestCSRFProtection::test_csrf_can_be_disabled_via_config`, `test_b05_web_hardening.py:TestCSRFProtection::test_post_login_with_valid_token_succeeds`

### AUD-14 (Open redirect through next)
- **Approach**: Safe URL validation in `ui/app.py:_safe_next_url(target)`. Requires single leading `/` and rejects `//`, `/\`, backslashes `\`, and schemes/netloc via `urlsplit`. Applied to query, form, and JSON login/register endpoints, falling back to `/dashboard`.
- **Files touched**: `ui/app.py`
- **Tests added**: `test_b05_web_hardening.py:TestOpenRedirect::test_login_rejects_scheme_redirect`, `test_b05_web_hardening.py:TestOpenRedirect::test_login_rejects_protocol_relative_redirect`, `test_b05_web_hardening.py:TestOpenRedirect::test_login_rejects_backslash_redirect`, `test_b05_web_hardening.py:TestOpenRedirect::test_login_allows_valid_relative_redirect`, `test_b05_web_hardening.py:TestOpenRedirect::test_json_login_sanitizes_next_redirect`

### AUD-15 (Unsafe server defaults)
- **Approach**: Server binds to `config.HOST` (default `127.0.0.1`, `AUTOSEC_HOST` override, loopback warning), eliminating literal `host="0.0.0.0"`. `SECRET_KEY` persisted to `data/.secret_key` via atomic `os.open` with `0o600` mode. In-memory login throttling operates via atomic critical section `_reserve_login_attempt(client_ip)` strictly keyed on `request.remote_addr`, preventing race bypasses during password verification.
- **Files touched**: `config.py`, `main.py`, `ui/app.py`
- **Tests added**: `test_b05_web_hardening.py:TestUnsafeServerDefaults::test_no_literal_host_0000_in_code`, `test_b05_web_hardening.py:TestUnsafeServerDefaults::test_secret_key_persistence_across_processes`, `test_b05_web_hardening.py:TestUnsafeServerDefaults::test_login_throttling_triggers_429_on_sixth_failure`, `test_b05_web_hardening.py:TestUnsafeServerDefaults::test_login_throttling_cannot_be_bypassed_with_rotated_xff`, `test_b05_web_hardening.py:TestUnsafeServerDefaults::test_login_throttling_parallel_threads_race_free`
