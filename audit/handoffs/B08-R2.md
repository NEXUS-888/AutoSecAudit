# Handoff B08-R2

## Target Issues
- **AUD-22**: Auto-login reports success on failed logins (`core/authenticator.py`)
- **AUD-23**: Credential spraying across 14 paths -> account lockout (`core/authenticator.py`)
- **AUD-24**: Crawler follows logout/destructive links and leaves scope on redirect (`core/crawler.py`)

## Review Feedback Addressed (from B08-R1)
1. **[AUD-22] Test double inspection removed from production code**:
   - Completely deleted `is_mock_return_val` and test-double detection logic from `_verify_authenticated_session`.
   - Grep verification confirms zero occurrences of `side_effect` or `return_value` in `core/authenticator.py`.
   - Updated `test_auto_authenticator.py:test_json_api_login_success` mock `get` with `side_effect` returning 401 without `Authorization` and 200 with it, leaving assertions untouched.
2. **[AUD-22] Post-login verification baseline differentiation**:
   - Branch E in `_verify_authenticated_session` updated: cookies plus 200 alone is never enough. The verified response must differ from the baseline via status change (401/403/login-redirect -> 200), POST redirecting away from login (`is_redirect_away`), newly present logout/username indicators, or material body difference from `anon_text` (at least 20 chars difference).
   - Added test `test_aud22_root_200_and_post_rotates_cookie_returns_200_unmatched_records_fails` asserting `success == False` when root returns 200 "Home page" and POST rotates `sid` while returning 200 "Those details don't match our records".
3. **[AUD-23] JSON probe qualification during auto-discovery**:
   - Dropped `is_json_resp` as a qualification in `_try_login_at_endpoint`. During auto-discovery, credentials are only sent to JSON endpoints if an empty `{}` POST returns 400, 401, or 422.
   - Added test `test_aud23_all_paths_get_200_json_and_empty_post_200_sends_zero_credential_posts` asserting 0 credential POSTs when GET returns 200 JSON and empty POST returns 200.
4. **[AUD-23/AUD-22] Username `@` prioritization**:
   - In `_attempt_json_api_login`, when `self.username` contains `@`, payload variations prioritize `{"email": ...}` first before `username` or `identifier`.
   - Updated Juice Shop test and added `test_aud23_email_field_sent_first_when_username_contains_at` confirming that endpoints returning 401 to `username` receive `email` on the first credential POST, succeed, capture token, and do not exceed the cap of 6.
5. **[Notes] Crawler deny pattern scope and redirect chain protection**:
   - Updated `_is_denied` in `core/crawler.py` to match only path and query (ignoring hostname/domain), preventing false positives on hosts like `remove-me.lab` or `delete.local`. Tested in `test_aud24_crawler_allows_target_domain_containing_deny_words`.
   - Added check on response URL and `resp.history` in `_crawl_page` to discard redirect chains landing on denied URLs. Tested in `test_aud24_crawler_discards_redirect_chain_hitting_denied_url`.
   - Wired `_is_clear_credential_rejection` into `_evaluate_auth_response` and added `DEFAULT_DENY_PATTERN` to filter login candidate paths in `core/authenticator.py`.
