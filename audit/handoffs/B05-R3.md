## Per-issue details
### AUD-13 (No CSRF protection)
- **Approach**: Flask-WTF `CSRFProtect` integration in `ui/app.py` via `AutoSecCSRFProtect`, protecting all state-changing endpoints (`/login`, `/register`, `/scan`, `/scan/async`). Supports hidden input `csrf_token`, headers (`X-CSRFToken`), and JSON payloads. Can be disabled via `app.config["WTF_CSRF_ENABLED"] = False`. Tested via `unittest.TestCase` discovery.
- **Files touched**: `requirements.txt`, `ui/app.py`, `ui/templates/auth.html`, `ui/templates/landing.html`, `test_b04_auth.py`, `test_target_reachability.py`, `test_silent_failures.py`
- **Tests added**: `test_b05_web_hardening.py:TestCSRFProtection::test_post_login_without_csrf_returns_400`, `test_b05_web_hardening.py:TestCSRFProtection::test_post_register_without_csrf_returns_400`, `test_b05_web_hardening.py:TestCSRFProtection::test_post_scan_async_without_csrf_returns_400`, `test_b05_web_hardening.py:TestCSRFProtection::test_csrf_can_be_disabled_via_config`, `test_b05_web_hardening.py:TestCSRFProtection::test_post_login_with_valid_token_succeeds`

### AUD-14 (Open redirect through next)
- **Approach**: Safe URL validation in `ui/app.py:_safe_next_url(target)`. Requires single leading `/` and rejects `//`, `/\`, backslashes `\`, and schemes/netloc via `urlsplit`. Applied to query, form, and JSON login/register endpoints, falling back to `/dashboard`.
- **Files touched**: `ui/app.py`
- **Tests added**: `test_b05_web_hardening.py:TestOpenRedirect::test_login_rejects_scheme_redirect`, `test_b05_web_hardening.py:TestOpenRedirect::test_login_rejects_protocol_relative_redirect`, `test_b05_web_hardening.py:TestOpenRedirect::test_login_rejects_backslash_redirect`, `test_b05_web_hardening.py:TestOpenRedirect::test_login_allows_valid_relative_redirect`, `test_b05_web_hardening.py:TestOpenRedirect::test_json_login_sanitizes_next_redirect`

### AUD-15 (Unsafe server defaults)
- **Approach**: Replaced literal `host="0.0.0.0"` in `main.py` and `ui/app.py` with `config.HOST` (default `127.0.0.1`, `AUTOSEC_HOST` override, loopback warning). Persisted `SECRET_KEY` to `data/.secret_key` with `0o600` permissions. Keyed login failure throttling strictly to `request.remote_addr`, blocking the 6th failed attempt from an IP within 5 minutes with 429. Added unit test explicitly verifying that spoofing/rotating `X-Forwarded-For` from the same client IP does not bypass the throttle.
- **Files touched**: `config.py`, `main.py`, `ui/app.py`
- **Tests added**: `test_b05_web_hardening.py:TestUnsafeServerDefaults::test_no_literal_host_0000_in_code`, `test_b05_web_hardening.py:TestUnsafeServerDefaults::test_secret_key_persistence_across_processes`, `test_b05_web_hardening.py:TestUnsafeServerDefaults::test_login_throttling_triggers_429_on_sixth_failure`, `test_b05_web_hardening.py:TestUnsafeServerDefaults::test_login_throttling_cannot_be_bypassed_with_rotated_xff`
