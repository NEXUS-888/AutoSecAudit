## AUD-48 — Reflection reported as command execution (Command Injection Accuracy)
- Changes: `plugins/command_injection_plugin.py`:
  - **Arithmetic Execution Probe:** Added probe `; echo AUTOSEC_$((6*7))_RCE; #` expecting output `AUTOSEC_42_RCE`. This proof cannot be produced by simple parameter reflection. Also verified testbed marker `command output: AUTOSEC_RCE_TEST`.
  - **Inert Control Probe:** Replaced executing control probe with inert probe `AUTOSEC_INERT_PROBE` containing zero shell metacharacters. If the server merely echoes the parameter without command execution proof, it is discarded as a reflector.
  - **Echo-and-Run Support:** Removed blanket `if payload in response.text: is_reflection = True` suppression so sinks that echo the executed command alongside command output (such as `testbed/app.py:exec_service`) are correctly reported.
  - **Timing POST Body:** Fixed timing probes (`probe_safe`, `probe_delay`, `probe_fast`) to send `json_data` and `data` bodies for POST requests.
  - **Duplicate Endpoint Guard:** Added check in JSON body fuzzing step to skip endpoints already flagged during parameter fuzzing, preventing duplicate findings on `/api/exec`.
- Criteria → tests:
  - Fake server executing command and echoing input yields exactly 1 finding → `test_b18_accuracy.py::TestB18Accuracy.test_aud48_echo_and_run_server_yields_finding`
  - Fake echo server yields 0 command injection findings → `test_b18_accuracy.py::TestB18Accuracy.test_aud48_echo_server_yields_no_command_injection_finding`
  - Real command execution reported → `test_b18_accuracy.py::TestB18Accuracy.test_aud48_real_command_execution_is_reported`
  - Testbed integration via Flask `test_client()`: `/api/exec` reported; `/search`, `/fetch`, `/template`, `/view` not reported → `test_b18_accuracy.py::TestB18Accuracy.test_aud48_testbed_app_execution_and_suppression`

## AUD-49 — Content-type-blind detections and differential login bypass baseline
- Changes: `plugins/sqli_plugin.py`:
  - **Differential Login Baseline:** In `_test_login_endpoints()`, sends a baseline control login request using benign invalid credentials (`autosec_invalid_user` / `wrong_password_999`).
  - **Differential Signal Verification:** Compares injected response against the control baseline. Only flags SQLi authentication bypass if the injected response exhibits a success signal that the control lacks:
    - Redirect to a location differing from both the login path and the control's redirect target (e.g. not a constant 302 to `/login?error=1`).
    - New session cookie not present in the control response (suppressing servers setting cookies on every request).
    - HTTP 2xx success status when control returned 401/403.
- Changes: `plugins/xss_plugin.py` & `plugins/ssrf_plugin.py`:
  - Preserved HTML content-type checking in XSS (`_is_html_rendered(response)`).
  - Preserved SSRF payload stripping and fetched internal marker verification.
- Criteria → tests:
  - Server answering constant 302 to `/login?error=1` and setting cookie on every response yields 0 findings → `test_b18_accuracy.py::TestB18Accuracy.test_aud49_login_constant_redirect_with_cookie_yields_no_finding`
  - Form-encoded POST login bypass yields finding → `test_b18_accuracy.py::TestB18Accuracy.test_aud49_login_sqli_form_encoded_bypass`
  - XSS ignored on `application/json` `/fetch` → `test_b18_accuracy.py::TestB18Accuracy.test_aud49_xss_ignored_on_json_content_type`
  - SSRF ignored on `/view` reflection → `test_b18_accuracy.py::TestB18Accuracy.test_aud49_ssrf_requires_fetched_evidence_not_mere_reflection`
  - Testbed integration via Flask `test_client()`: no XSS on `/fetch`, no SSRF on `/view`, and SQLi reported on `/login` → `test_b18_accuracy.py::TestB18Accuracy.test_aud49_testbed_content_type_and_login`
