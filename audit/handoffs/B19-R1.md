# Handoff B19 round 1

## AUD-62 — The open-redirect false-positive fix now misses real evasion forms (regression)
- Changes: `plugins/open_redirect_plugin.py:102-117`:
  - Normalized `Location` header in `_redirects_to_external_host(request_url, location)` before resolving with `urljoin`:
    1. Converts backslashes `\` to `/`.
    2. Collapses a leading run of three or more `/` (`^/{3,}`) to `//`.
    3. Normalizes `scheme:host` and `scheme:/host` forms (`^([a-zA-Z][a-zA-Z0-9+.-]*):/*`) to `\1://`.
    4. Resolves against `request_url` and flags only when the resolved hostname is `example.com` or `*.example.com`, keeping same-site echo paths (`/login/?next=https%3A%2F%2Fexample.com`) unflagged.
- Criteria → tests:
  - With `request_url="http://127.0.0.1:5103/redirect?next=PAYLOAD"`, flags `https://example.com`, `//example.com/x`, `/\example.com`, `\\example.com`, `///example.com`, `HTTPS://EXAMPLE.COM`, `https:example.com`, `https:/example.com`, `http://127.0.0.1@example.com/`, `https://attacker.example.com/`; does not flag `/login/?next=https%3A%2F%2Fexample.com`, `https://example.com.evil.net/`, `https://notexample.com/`, `""` → `test_b19_scanner_robustness.py::TestAud62OpenRedirectEvasion.test_aud62_open_redirect_evasion_and_non_evasion_rows`

## AUD-64 — No response-size or total-time limit on requests to the target
- Changes: `config.py:107-155`:
  - Added `MAX_RESPONSE_BYTES` (default 5 MiB, env `AUTOSEC_MAX_RESPONSE_BYTES`, range 64 KiB–100 MiB) and `MAX_REQUEST_SECONDS` (default 30, env `AUTOSEC_MAX_REQUEST_SECONDS`, range 1–300) via `_load_bounded_int`, logging a warning and falling back to defaults on invalid values.
- Changes: `core/http_client.py:70-185, 385-690`:
  - Added thread-safe counters `responses_truncated` and `requests_timed_out` on `ScanHttpClient`.
  - Updated `_execute_with_redirects()` to send requests with `stream=True` and consume bodies in chunks via `_consume_bounded_body()` up to `config.MAX_RESPONSE_BYTES` and `config.MAX_REQUEST_SECONDS` of total wall time per request.
  - On hitting either limit, closes the stream, preserves the body read so far (`resp._content` / `resp._content_consumed = True` so `.text`, `.content`, and `.json()` keep working), sets `resp.truncated = True` (`False` otherwise), and increments `responses_truncated` or `requests_timed_out`.
- Criteria → tests:

  - 10 bytes/s dripping fixture for 60s stopped at `MAX_REQUEST_SECONDS=3` within ~4s with `truncated=True` → `test_b19_scanner_robustness.py::TestAud64ResponseSizeAndTimeLimits.test_aud64_dripping_response_stopped_at_max_request_seconds`
  - Normal small response unchanged and `truncated=False` → `test_b19_scanner_robustness.py::TestAud64ResponseSizeAndTimeLimits.test_aud64_normal_small_response_unchanged_and_not_truncated`
