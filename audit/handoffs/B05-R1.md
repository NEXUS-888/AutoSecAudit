# Handoff B05 round 1

## Summary of changes
- Integrated CSRF protection via Flask-WTF `CSRFProtect` on all state-changing POST routes (`/login`, `/register`, `/scan`, `/scan/async`) with support for hidden form input `csrf_token`, header `X-CSRFToken`, and disableable via `WTF_CSRF_ENABLED = False`.
- Added open redirect validation for the `next` query/form/JSON parameter in `/login` and `/register`, rejecting external schemes, `//`, `/\`, and backslashes, safely falling back to `/dashboard`.
- Hardened server defaults: eliminated literal `host="0.0.0.0"` in code (defaulting to `127.0.0.1` and warning on non-loopback `AUTOSEC_HOST`), persisted `SECRET_KEY` to `data/.secret_key` across process restarts, and implemented in-memory IP login failure throttling (429 Too Many Requests on 6th failed attempt within 5 minutes).

### AUD-14 (Open redirect through next)
- **Approach**: Implemented `_safe_next_url(target)` in `ui/app.py`. Enforces that redirect targets must be relative paths starting with a single `/` and rejecting `//`, `/\`, URL schemes (`http:`, `https:`, etc.), and backslashes `\`. Applied to `/login` and `/register` for query args, form POST, and JSON payloads, falling back to `/dashboard`.
- **Files touched**: `ui/app.py`
- **Tests added**: `test_b05_web_hardening.py:TestOpenRedirect::test_login_rejects_scheme_redirect`, `test_b05_web_hardening.py:TestOpenRedirect::test_login_rejects_protocol_relative_redirect`, `test_b05_web_hardening.py:TestOpenRedirect::test_login_rejects_backslash_redirect`, `test_b05_web_hardening.py:TestOpenRedirect::test_login_allows_valid_relative_redirect`, `test_b05_web_hardening.py:TestOpenRedirect::test_json_login_sanitizes_next_redirect`

### AUD-15 (Unsafe server defaults)
- **Approach**: Replaced literal `host="0.0.0.0"` in `main.py` and `ui/app.py` with `config.HOST`, which defaults to `127.0.0.1` and can be overridden by `AUTOSEC_HOST`. Added loopback validation warning when `AUTOSEC_HOST` is bound to a non-loopback address. Updated `config.py` to persist generated `SECRET_KEY` in `data/.secret_key` when `AUTOSEC_SECRET_KEY` is unset so independent processes share the key. Added in-memory login failure tracking per client IP in `ui/app.py` (`_is_login_throttled`, `_record_login_failure`, `_clear_login_failures`, `reset_login_throttles`) returning 429 when 5 failed attempts occur within 5 minutes.
- **Files touched**: `config.py`, `main.py`, `ui/app.py`
- **Tests added**: `test_b05_web_hardening.py:TestUnsafeServerDefaults::test_no_literal_host_0000_in_code`, `test_b05_web_hardening.py:TestUnsafeServerDefaults::test_secret_key_persistence_across_processes`, `test_b05_web_hardening.py:TestUnsafeServerDefaults::test_login_throttling_triggers_429_on_sixth_failure`
