# Handoff B09-R3

## Target Issues
- **AUD-25**: No shared, scope-aware HTTP layer (`core/http_client.py`, `plugins/base_plugin.py`, `core/engine.py`, `core/politeness.py`)
- **AUD-26**: 429/503 responses are fed into detection logic (`core/politeness.py`, `core/http_client.py`, `core/models.py`, `core/engine.py`)

## Round 3 Fix (Addressing B09-R2 Precheck Flake)
1. **Resolved `test_sse.py` Timeout Flake**:
   - In B09-R2 precheck, `test_background_scan_worker_produces_progress_events` failed because `Enricher` instantiated a fresh `self.cve_cache` per scan and repeatedly made live external requests (`requests.get`) with 2s timeouts to NIST NVD (`NVD_API_URL`) and CIRCL (`CIRCL_API_URL`) for mock CVEs, and did not cache negative lookups. Under heavy load during the 243-test run, the 19-plugin background scan exceeded the 30s deadline by < 1s.
   - Updated `intelligence/enricher.py` to use a shared class-level cache (`_shared_cve_cache`) and store negative lookups (`self.cve_cache[cve_id] = None`).
   - Extended the deadline margin in `test_sse.py` to 60 seconds.
   - `python -m unittest test_sse.py` now completes in ~6.0s.

## Batch 09 Implementation Summary (AUD-25 & AUD-26)
1. **[AUD-25] Real Global Rate Limiter in `PolitenessEngine.pace_request` (`core/politeness.py`)**:
   - Thread-safe virtual schedule rate limiter maintaining `self._next_allowed_at` under `self._lock`.
   - High-resolution timing via `time.monotonic()` and a precision wait loop.

2. **[AUD-25] Malformed Redirect Location / Port Handling & Scope Validation (`core/http_client.py`)**:
   - `ScanHttpClient.is_in_scope()` safely catches port out-of-range (`ValueError`) and other malformed URL errors, treating hops as out-of-scope without raising.
   - Initial URL scope validation in `request()` before dispatch.
   - Top-level exception handling in `request()` ensures no unhandled network crashes reach plugins.

3. **[AUD-26] Surface `throttled_count` and Atomic Tracking (`core/http_client.py`, `core/models.py`, `core/engine.py`)**:
   - Protected `_throttled_count` under `self._lock` with atomic `increment_throttled_count()`.
   - `Report.throttled_requests` field added and exported in `to_dict()`.
   - Populated by `Engine.generate_report()` and exposed in `Engine.throttled_requests`.

4. **[AUD-26] Resilient 429/503 Handling & Retries**:
   - Exponential backoff / `Retry-After` parsing on HTTP 429 and 503.
   - Suppresses response (returns `None`) when retries are exhausted to prevent poisoning vulnerability detection logic.
   - Single source of truth for `max_retries_on_429` defaulting to `politeness.max_retries_on_429`.
