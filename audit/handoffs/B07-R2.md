## AUD-19 — Atomic Slot Reservation under Concurrent Load
- Feedback addressed: The cap was a check-then-act race across multiple requests.
- Changes: `ui/app.py:209-224` — Added atomic `try_reserve(scan_id, job_dict)` to `BoundedScanExecutor`. Inside a single critical section guarded by `with scan_jobs_lock:`, `try_reserve` inspects active counts and registers the job entry with status `"starting"`.
- Changes: `ui/app.py:196-201` — Added `_is_job_active(job)` helper that safely checks `t is None or getattr(t, "ident", None) is None or t.is_alive()`, ensuring threads in the pre-start phase remain counted.
- Changes: `ui/app.py:226-231` — `submit(job_dict, fn, ...)` calls `t.start()` and assigns `job_dict["thread"] = t`.
- Changes: `ui/app.py:2768-2815` — In `scan_async()`, slot reservation occurs atomically via `try_reserve` before any file or background setup. If setup fails thereafter, `scan_jobs.pop(scan_id, None)` cleans up the slot under lock.
- Criteria → tests: ≥8 concurrent `POST /scan/async` requests behind a `threading.Barrier` with `AUTOSEC_MAX_CONCURRENT_SCANS=1` and `_run_scan_background` patched to sleep yield exactly one 200 response and seven 429 responses → `test_b07_scan_management.py::TestB07ScanManagement.test_aud19_concurrent_barrier_atomic_reservation`.

## AUD-20 — Race-Free Terminal Event Delivery
- Feedback addressed: Lost-terminal-event race caused by terminal `status` becoming visible before terminal events were appended inside condition lock, combined with bare status-based `break` in `scan_progress`.
- Changes: `ui/app.py:236-258` — Updated `_emit_job_event` to accept `status: str = None` and set `job["status"] = status` atomically inside `with cond:` when emitting events. Removed unused write-only `progress_queue` buffer.
- Changes: `ui/app.py:269-278` — Updated `_cleanup_stale_jobs()` to emit the timeout error event and transition status via `_emit_job_event(..., status="error")` inside condition lock.
- Changes: `ui/app.py:2602-2713` — In `_run_scan_background`, worker passes `status="done"` and `status="error"` to `emit()`, so status and event are synchronized. Added cancellation check between pipeline stages and guaranteed error transition in `finally` if worker terminates unexpectedly.
- Changes: `ui/app.py:2854-2892` — In `scan_progress()`, removed the premature bare `if job.get("status") in ("done", "error"): break` check. The subscriber stream only terminates when an event with stage `"done"` or `"error"` has been delivered (`is_done`).
- Criteria → tests: Setting a job's `status="done"` with only a non-terminal event in `events`, connecting a subscriber, then emitting `done` via `_emit_job_event` results in the subscriber reliably receiving the `"done"` event → `test_b07_scan_management.py::TestB07ScanManagement.test_aud20_subscriber_receives_done_when_status_already_done_before_event`.
