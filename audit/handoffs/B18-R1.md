# Handoff B18 round 1

## AUD-48 — Reflection reported as command execution (4 Critical false positives)
- Changes: `plugins/command_injection_plugin.py`:
  - In `run()`, for each test payload, now sends a matched control request using a safe control probe prefix (`AUTOSEC_CTRL_TEST`) instead of the command execution payload.
  - Compares the test response with the control response: if the marker text appears identically in both responses (meaning the server merely reflected the parameter back, e.g. `/search`, `/fetch`, `/template`, `/view`), it is recognized as reflection and suppressed.
  - OS command injection is reported only when the response contains command execution evidence that the control reflection cannot produce.
  - Retained statistical timing-based verification backed by `TimingVerifier`.
- Criteria → tests:
  - Echo server yields no command injection findings → `test_b18_accuracy.py::TestB18Accuracy.test_aud48_echo_server_yields_no_command_injection_finding`
  - Real command execution at `/api/exec` is reported → `test_b18_accuracy.py::TestB18Accuracy.test_aud48_real_command_execution_is_reported`

## AUD-49 — Content-type-blind detections and a missed login injection
- Changes: `plugins/xss_plugin.py`:
  - Added `_is_html_rendered(response)` check verifying `Content-Type` is HTML (`text/html`) or empty/unspecified non-binary, suppressing reflected XSS on non-HTML responses (e.g. `application/json` on `/fetch`).
- Changes: `plugins/ssrf_plugin.py`:
  - Strips payload and URL-encoded variations from response text before checking evidence markers.
  - Requires evidence tied to internal destination/service (`instance-id`, `ami-id`, `security-credentials`, `simulated_internal_response`, `ssh-`, `root:x:0:0`, `redis_version`, loopback markers outside reflection, or 502/504 status codes). Parameter reflection on file-path endpoints (such as `/view`) is no longer reported.
- Changes: `plugins/sqli_plugin.py`:
  - In `_test_login_endpoints()`, extracts form fields discovered by crawler (`self.discovered_endpoints`) with fallback defaults.
  - Submits both form-encoded (`application/x-www-form-urlencoded` with `data=body`) and JSON (`application/json` with `json_data=body`) requests.
  - Detects authentication bypass via HTTP 302/redirects, session cookies, and auth response heuristics.
- Changes: `plugins/base_plugin.py`:
  - Fixed missing `import time` in `plugins/base_plugin.py`.
- Criteria → tests:
  - Reflected XSS ignored on `application/json` `/fetch` → `test_b18_accuracy.py::TestB18Accuracy.test_aud49_xss_ignored_on_json_content_type`
  - SSRF not reported on `/view` parameter reflection, reported on `/fetch` → `test_b18_accuracy.py::TestB18Accuracy.test_aud49_ssrf_requires_fetched_evidence_not_mere_reflection`
  - Form-encoded POST login bypass on `/login` reported → `test_b18_accuracy.py::TestB18Accuracy.test_aud49_login_sqli_form_encoded_bypass`

## AUD-50 — Same issue reported several times across plugins
- Changes: `core/models.py`:
  - Implemented `normalize_endpoint_path(endpoint)`: normalizes numeric path segments (e.g. `/api/users/1`) to `{id}` (`/api/users/{id}`).
  - Implemented `compute_canonical_key(vuln_type, method, endpoint, param)`: canonical key formatted as `vuln_type|method|normalized_endpoint|param`.
  - Added `compute_canonical_key()` method to `Finding`.
  - Added `reporting_tools: List[str]` field on `Finding` to track all tools reporting the finding.
- Changes: `intelligence/correlator.py`:
  - Added `merge_canonical(findings)`: groups findings by canonical key, retains highest-confidence evidence, compiles list of all reporting tools into `reporting_tools`, and unifies severity using canonical severity mapping from AUD-37.
  - Updated `link_related(findings, cross_tool=False)`: default preserves distinct titles within individual tools while optional `cross_tool=True` delegates to `merge_canonical`.
- Changes: `core/pipeline.py`:
  - In unified scan pipeline Step 9, invokes `correlator.merge_canonical` so cross-tool duplicate findings are merged into a single canonical finding before report generation.
- Criteria → tests:
  - Canonical key normalizes numeric path segments to `{id}` → `test_b18_accuracy.py::TestB18Accuracy.test_aud50_canonical_key_normalizes_numeric_path_segments`
  - Cross-tool merging keeps highest confidence, lists reporting tools, unifies severity → `test_b18_accuracy.py::TestB18Accuracy.test_aud50_cross_tool_merging`
  - `/.env` (3x), `/admin` (2x), `/api/exec` (2x), and IDOR (2x) merged to exactly 1 each → `test_b18_accuracy.py::TestB18Accuracy.test_aud50_multiple_issue_deduplication`
